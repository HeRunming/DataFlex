CRITICAL FINDINGS (Must Fix Before Paper Publication)
================================================================================

1. GRADIENT TYPE MISMATCH (🔴 CRITICAL)
   ─────────────────────────────────────────────────────────────────────────
   LESS Configuration:
   - Training gradients: Adam (β₁=0.9, β₂=0.999)
   - Target gradients:   SGD (raw)
   
   MMD Configuration:
   - Training gradients: SGD (raw)
   - Target gradients:   SGD (raw)
   
   Impact: Different gradient representations → Unfair comparison
   
   Fix: Change components.yaml
        mmd_grad_rbf: gradient_type → adam  (line 64)
        mmd_grad_cov: gradient_type → adam  (line 76)

   
2. ADAM PRECONDITIONING BUG (🔴 CRITICAL)
   ─────────────────────────────────────────────────────────────────────────
   LESS (less_selector.py, lines 125-133):
   ✗ In-place mutation of optimizer state v
   ✗ denom = v.mul(beta2)  ← corrupts v!
   
   MMD (mmd_selector.py, lines 645-654):
   ✓ Creates new tensors (non-destructive)
   ✓ Correct Adam formula without state corruption
   
   Impact: LESS implementation may have numerical instability
   
   Fix: Update LESS to use MMD's approach:
        numerator = beta1 * m + (1.0 - beta1) * g
        denominator = sqrt(beta2 * v + (1.0 - beta2) * g²) + eps
        result = numerator / denominator


3. RANDOM PROJECTION SEED MISMATCH (🟠 HIGH)
   ─────────────────────────────────────────────────────────────────────────
   LESS seed: 123      (components.yaml line 40)
   MMD seed:  42       (components.yaml lines 54, 66, 78)
   
   Impact: Different random projection matrices → Breaks reproducibility
   
   Fix: Standardize to same seed. Option A (recommended):
        Use seed=42 for all methods (more common)
        Or seed=123 for all methods (current LESS choice)


4. TARGET_DATASET PARAMETER UNUSED (🟠 HIGH)
   ─────────────────────────────────────────────────────────────────────────
   Field defined: dynamic_params.py lines 560-568
   Implementation: select_trainer.py lines 250-254 (does nothing!)
   
   Current behavior:
   - If user sets target_dataset in YAML → ignored
   - Always falls back to eval_dataset
   
   Impact: Cannot specify independent target set for selection
   
   Fix: Implement actual target_dataset loading in SelectTrainer:
        if finetuning_args.target_dataset:
            target_dataset_for_selector = load_dataset(target_dataset)
        else:
            target_dataset_for_selector = eval_dataset


5. EVALUATION DATA LEAKAGE (🟠 HIGH)
   ─────────────────────────────────────────────────────────────────────────
   LESS baseline config (less_baseline.yaml):
   - eval_dataset: alpaca_zh_demo
   - Used for: selection AND evaluation metrics
   
   Problem: Same dataset for selection target AND eval metrics
           Violates LESS paper protocol (should be separate)
   
   LESS paper expects:
   - Candidate pool: Large training data (100k+)
   - Target set: Few-shot examples (64)  ← For selection only
   - Evaluation: Held-out test split     ← Separate dataset
   
   Current DataFlex: alpaca_zh_demo is used for both target & eval
   
   Fix: Use separate datasets:
        - eval_dataset: held-out test split (for metrics)
        - target_dataset: few-shot examples (for selection)

MEDIUM FINDINGS (Design Differences)
================================================================================

6. SELECTION SCORING METHODOLOGY
   ─────────────────────────────────────────────────────────────────────────
   LESS:
   - Score: cosine_similarity(train_grads, target_grads)
   - Selection: top-k highest similarity
   - No redundancy penalty
   
   MMD:
   - Score: Δ(x) = r_T(x) - (1/(m+1)) * [r_S(x) + k(x,x)/2]
   - Selection: greedy argmax (iterative)
   - Includes redundancy penalty within selected set
   
   Status: Different by design (expected trade-off)


7. EVALUATION PROTOCOL INCONSISTENCY
   ─────────────────────────────────────────────────────────────────────────
   LESS baseline (less_baseline.yaml):
   - eval_strategy: steps
   - eval_steps: 10
   → Evaluates every 10 steps during training
   
   MMD configs (mmd_grad_rbf.yaml, mmd_grad_cov.yaml):
   - eval_strategy: "no"
   → No evaluation during training
   
   Impact: Different training dynamics, unfair comparison
